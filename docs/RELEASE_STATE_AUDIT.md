## 7. Remote synchronization (Phase 7) — BLOCKED

Push is blocked: no GitHub credentials in the sandbox; `git push` fails with
`fatal: could not read Username for 'https://github.com'`. Additionally the local `main` and
`origin/main` have **no common ancestor** (parallel lineages), so `main` must never be pushed to
`origin/main`. Safe publication is a NEW branch plus tags, per `docs/PUSH_RELEASE_INSTRUCTIONS.md`:

```bash
# Ship path A (from a machine with credentials, using the verified bundle):
git fetch /path/to/mbumah-v2.18.2.1-release.bundle 'refs/heads/main:refs/heads/sandbox-release'
git push origin sandbox-release:refs/heads/release/v2.18.2.1-org-console
git push origin refs/tags/v2.18.2 refs/tags/v2.18.2.1

# Ship path B (token provided to the sandbox):
export GH_TOKEN=<owner-token>
git remote set-url origin "https://x-access-token:${GH_TOKEN}@github.com/bucky-ops/mbumah-hardware-pos.git"
git push origin main:refs/heads/release/v2.18.2.1-org-console
git push origin refs/tags/v2.18.2 refs/tags/v2.18.2.1
git remote set-url origin https://github.com/bucky-ops/mbumah-hardware-pos.git

# GitHub release (after tags are remote, where gh is authenticated):
gh release create v2.18.2.1 --title "v2.18.2.1" --notes-file CHANGELOG.md --latest
```

Integration warning: `origin/main` uses a different data model (`Store`/`SalesTransaction`,
88-model PostgreSQL schema) than this release lineage (`Branch`/`Transaction`, 43-model SQLite
schema). Do not fast-forward `origin/main`; reconcile per
`docs/PUSH_RELEASE_INSTRUCTIONS.md` section 5 before tagging from the main lineage.
