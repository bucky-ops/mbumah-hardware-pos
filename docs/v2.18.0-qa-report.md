# v2.18.0 Full QA and Release Verification Report

Release: 2.18.0 (verification release)
Baseline audited: 2.17.9 (main at e76a310)
Date: 2026-10-13
Method: static gates plus hygiene sweeps, a 21-check runtime matrix against a seeded SQLite development server, and a browser walkthrough with agent-browser. Prior documented evidence from v2.17.3 and v2.17.5 is referenced as such and was not re-executed.

## 1. Executive summary

The v2.17.x feature line (branch workspaces and organization console, LAN hosting, online subdomains, security and tenant isolation hardening, staged updates) passed a full verification cycle. All four quality gates match the 2.17.9 baselines exactly. The runtime matrix passed 21 of 21 checks covering authentication, role-based access, tenant isolation, workspace resolution in all three hosting modes, the staged updater contract and the global chat API. The browser walkthrough confirmed the organization console login flow and the five branch workspace links.

No product defects were found in this cycle. The only non-ok health check is the pre-existing advisory "Sentry not configured" warning. One QA-environment footgun (a globally exported DATABASE_URL in the operator shell overriding the project .env for spawned processes) is documented in the known gaps so future local QA runs pin the database variables explicitly.

Verdict: PASS. The 2.18.0 release is a verification release; no runtime behavior changes are intended. The version bump, release notes and this report are the only changes.

## 2. Scope and method

Static QA:

- lint (next lint), typecheck (tsc, advisory), vitest suite, prisma validate.
- Hygiene sweeps with ripgrep over src and docs: broken store links, guard coverage, security headers, forwarded-host flag default, rate limiting coverage, security event coverage, tracked secrets or database files, em and en dash characters.

Runtime QA (one session, dev server on localhost:3100, seeded SQLite database at prisma/prisma/dev.db, version under test reporting 2.17.9):

- Authentication: admin and cashier logins against POST /api/auth/login.
- Authorization and tenant isolation: store-context allow and deny, cross-store record probes, 404-indistinguishability, update endpoint role gates.
- Workspace resolution: path gateway page, reserved subdomain labels, subdomain mode via Host header, x-forwarded-host default-off behavior.
- Staged updater: status endpoint field minimization, prepare endpoint 401/400/202/409 contract, state file handoff and reset.
- Observability: /api/health payload fields and per-check statuses.

Browser QA (agent-browser, same server): login as admin through the UI, verify the organization console and the branch workspace link targets.

## 5. Known gaps and recommendations

1. Sentry not configured (advisory, pre-existing). The health check reports a warning and production error telemetry is silent. Recommendation: wire the Sentry DSN for production or make the warning explicitly acknowledgment-based.
2. Staged updater rollback on real hardware (blocked in sandbox). The install-directory swap, database restore and smoke-test rollback path should be rehearsed once on a Windows laptop and once on a LAN host per docs/staged-updates.md, including a deliberately corrupted artifact.
3. M-Pesa live sandbox test (manual). STK push against the Safaricom Daraja sandbox needs credentials and a public callback; covered today by unit tests and the proxy PAYMENT rate-limit tier only.
4. QA environment footgun (environmental, not a product defect). A globally exported DATABASE_URL in the operator shell overrides the project .env for any spawned process (next dev, node, prisma children), which produced a misleading P2021 during this cycle until the QA runner pinned DATABASE_URL and DIRECT_URL explicitly. Recommendation: pin the two variables in QA scripts and note the precedence rule in the local development docs.
5. Typecheck advisory debt: 472 strict-mode errors tracked under issue #8; unchanged from baseline, zero in the files touched by this release.
6. Lint warning debt: 396 warnings (mostly no-console); unchanged from baseline.
